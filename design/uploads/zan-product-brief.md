# Zan — юридический ассистент для жителей РК. Продуктовый бриф v2

## 1. Контекст

Есть рабочий прототип (Q&A по законодательству РК с цитированием статей). Дизайн прототипа — временный, черновой, не финальный. Нужно спроектировать и собрать **новую версию** с расширенным функционалом и современным минималистичным дизайном.

**Аудитория:** обычные жители Казахстана без юридического образования — язык интерфейса и ответов должен быть простым, без канцелярита. Пользователи обращаются **нечасто** (не ежедневно), поэтому продукт должен быть понятен с первого захода, без обучения.

## 2. Дизайн-требования

- Современный, минималистичный, "воздушный" интерфейс — не перегруженный
- Mobile-first (большинство пользователей — с телефона), полностью адаптивный
- Поддержка светлой/тёмной темы
- Существующий переключатель Рус/Қаз — сохранить
- Доверие и спокойствие как эмоция дизайна (юридическая тема тревожная для пользователя — интерфейс должен успокаивать, не пугать)
- Чёткая иерархия: главное действие (задать вопрос) — всегда на виду, не нужно искать

## 3. Функциональные блоки

### 3.1 Главный экран — чат с ассистентом
- Формат полноценного диалога (тред), а не разовая форма "вопрос → один ответ"
- Ввод текстом
- Ввод голосом: надиктовка → распознавание речи в текст → редактирование перед отправкой
- Прикрепление файла к сообщению (для анализа документа)
- Переключатель/режим "Подготовить готовый документ" (как в прототипе) — генерирует документ, а не просто отвечает текстом
- Ответ ассистента:
  - Обычный текст простым языком
  - Сворачиваемый блок "Показать статьи закона / источники" — не занимает место по умолчанию
  - Кнопки 👍/👎 на ответ (обратная связь)
- Быстрые темы на пустом экране для новых пользователей (например: "Трудовые споры", "Регистрация ИП/бизнеса", "Семейное право", "Мигранты и трудоустройство") — клик подставляет черновик вопроса

### 3.2 Работа с файлами
- Загрузка документа (договор, решение суда, справка и т.д.) → анализ и ответ по содержимому в этом же треде
- Генерация нового документа (заявление, претензия, договор и т.д.) на основе диалога
- Результат — скачивание файла (PDF/Word)
- Поддерживаемые форматы загрузки: минимум PDF, DOCX, изображение (скан/фото документа)

### 3.3 История обращений
- Список тредов (не отдельных сообщений) с статусами: В очереди / Обрабатывается / Ждёт уточнения / Готово / Ошибка / Отменён
- Открытие треда — переход в полноценный чат с возможностью продолжить диалог
- Поиск/фильтр по статусу

### 3.4 Оплата (заглушка/mock)
**Модель: оплата за консультацию (тред), а не за сообщение.**
- Первое сообщение в новом треде → модалка оплаты ("Эта консультация стоит N ₸ / списывается 1 консультация с баланса") → имитация оплаты (без реальной интеграции) → после "оплаты" запрос уходит в обработку
- Все последующие уточняющие сообщения **внутри того же треда** — бесплатны, пока тред активен
- Генерация готового документа — отдельная платная опция (либо докупка внутри треда, либо отдельный платёж), дороже обычного вопроса
- Экран/блок баланса пользователя — сколько консультаций осталось

### 3.5 Тарифы (для пользователя — экран выбора и покупки, mock-оплата)
Модель — **пакеты консультаций**, НЕ помесячная подписка (обоснование: нерегулярное обращение аудитории):
- Пакет "1 консультация"
- Пакет "3 консультации" (скидка)
- Пакет "10 консультаций" (скидка больше)
- Срок действия пакета — длинный (6–12 месяцев) или бессрочный
- Опционально (второй эшелон, не основной сценарий): тариф "Безлимит на месяц" для активных пользователей (малый бизнес, бухгалтеры, HR)

### 3.6 Настройки (временный доступ всем, впоследствии — скрыть под админ-доступ)
- **Промпты агентов** — два текстовых поля с возможностью редактирования и сохранения:
  1. Промпт агента "Вопрос-ответ"
  2. Промпт агента "Работа с документами"
  - Кнопка "Сохранить" → отправка нового текста на бэкенд (обновление системного промпта агента)
- **Управление тарифами** — список тарифов с полями: название, описание, цена, кол-во консультаций/лимит, срок действия. Возможность редактировать существующие и добавлять новые
- Технически: предусмотреть, что в будущем этот раздел будет скрыт за авторизацией/ролью админа — не завязывать доступ жёстко на "все видят", закладывать разделение по роли с самого начала (даже если сейчас роль не проверяется)

## 4. Дополнительно (по желанию, можно закладывать по возможности)

- Экспорт диалога или документа в PDF
- Ненавязчивый юридический дисклеймер (один раз при первом входе, либо мелким текстом в футере — не на каждом экране)
- Пустые состояния (empty states) для истории и чата — не просто пустой экран

## 5. Не входит в этот этап (явно вне скоупа)

- Реальная интеграция платёжного провайдера — только заглушка/mock
- Полноценная система ролей и авторизации для админки — на этом этапе admin/settings открыт всем
- Многопользовательские аккаунты, командная работа

## 6. Технические заметки для реализации

- Данные для истории/тредов: id треда, статус, дата создания, дата последнего сообщения, список сообщений, привязанные файлы, статус оплаты
- Тарифы и промпты — должны читаться и обновляться через бэкенд (не хардкод в интерфейсе), т.к. заявлено "при сохранении обновлю в бэкенде"
- Голосовой ввод — на этом этапе только диктовка в текст (Speech-to-Text), без отправки/обработки самого аудиофайла ассистентом

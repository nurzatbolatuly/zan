# Zan — Техническое задание на бэкенд v4

Обновление v3 → v4. Меняется только распределение задач между Go и Python (архитектура), остальное — как в v3. Изменения:

- **Мгновенный Q&A (сам вызов LLM) — теперь в Go**, а не в Python. Go сам собирает промпт, вызывает LLM-провайдера и разбирает структурированный ответ — для обоих агентов (Q&A и "Документы").
- **В Python остаётся только**: работа с файлами (извлечение текста/OCR, рендер сгенерированных документов в PDF/DOCX), голос (STT) и **RAG-система** (поиск релевантных источников/статей закона по базе НПА).
- Соответственно RAG теперь — отдельный шаг: Go при необходимости запрашивает у Python релевantные источники **перед** тем, как сам вызвать LLM, и передаёт их LLM как часть контекста.

Все прочие разделы (§2–§8 из v3: сессии, данные, платежи, ошибки не связанные с этим изменением, логирование, открытые вопросы) остаются в силе без изменений — ниже приведены только пересобранные §1, §5.2 и §6.2, которые этот сдвиг затрагивает напрямую. Полный документ ниже собран целиком, чтобы не пользоваться двумя файлами одновременно.

---

## 1. Архитектура и разделение задач

### 1.1 Go — ядро системы (весь основной трафик, включая генерацию ответа)

- Сессии (создание, продление, идентификация)
- Треды и сообщения — CRUD, статусная модель, история
- **Q&A-агент целиком**: сборка истории треда + промпта из `AgentPrompt`, при необходимости — запрос источников у Python (RAG, см. §1.3), прямой вызов LLM-провайдера, разбор структурированного JSON-ответа, сохранение сообщения
- **Агент "Документы"**: аналогично — Go вызывает LLM напрямую для анализа/генерации текста документа; Python используется только для извлечения текста из загруженного файла (перед вызовом LLM) и для рендера итогового файла (после)
- Оплата (заглушка), баланс/кредиты по услугам
- Услуги и тарифы (публичные + админ CRUD)
- Промпты агентов — хранение, выдача и **использование** (в отличие от v3, где вызов LLM делал Python)
- Загрузка файлов — приём, валидация (тип/размер/антивирус), сохранение в хранилище, метаданные
- Аналитика
- Приём логов с фронта
- Оркестрация вызовов к Python-сервису (таймауты, ретраи, circuit breaker) — теперь используется для RAG/файлов/голоса, а не для генерации ответа

### 1.2 Python (FastAPI) — специализированные ML-задачи без генерации ответа

Внутренний сервис, вызывается только из Go:

- **RAG-поиск**: по тексту вопроса/треда находит релевантные статьи закона/источники в векторной базе, возвращает список кандидатов с оценкой релевантности — Go сам решает, что из этого передать в промпт LLM
- **Извлечение текста из файлов** (PDF/DOCX/изображения, включая OCR) — перед тем, как Go передаст текст в LLM
- **Рендер сгенерированного документа** в PDF/DOCX (после того, как Go получил текст документа от LLM)
- **STT** — распознавание голосовых сообщений в текст

### 1.3 Контракт Go ↔ Python (обновлён)

| Метод | Путь                         | Вызывается при                                                                             | Тело запроса                          | Ответ                                 |
| ----- | ---------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------- | ------------------------------------- |
| POST  | `/internal/rag/search`       | Go готовится вызвать LLM и нужны источники (обычно — каждый Q&A-запрос и анализ документа) | `{query_text, top_k}`                 | `{matches: [{ref, quote, score}]}`    |
| POST  | `/internal/files/extract`    | загружен файл на анализ                                                                    | `{file_url, mime_type}`               | `{extracted_text, pages, warnings[]}` |
| POST  | `/internal/documents/render` | после того как Go получил текст документа от LLM                                           | `{document_draft, format: pdf\|docx}` | файл (бинарь) или `{file_url}`        |
| POST  | `/internal/stt`              | голосовое сообщение                                                                        | multipart audio                       | `{text}`                              |

`X-Trace-Id` (= `thread_id`/`message_id`) обязателен в каждом вызове — см. §6.

### 1.4 Обновлённый пошаговый флоу обработки Q&A-сообщения

1. Go принимает сообщение, проверяет оплату/баланс (см. v3 §5.5)
2. Go запрашивает у Python `/internal/rag/search` с текстом вопроса (+ контекст треда) → получает кандидатов-источников
3. Go собирает финальный промпт: системный `AgentPrompt(qa)` + история сообщений треда + найденные источники
4. Go вызывает LLM-провайдера напрямую (HTTP-клиент к Anthropic/иному API)
5. Go разбирает структурированный ответ (`answer_text`, `sources`, `needs_clarification`), сверяя `sources` с тем, что реально вернул RAG (чтобы модель не "придумывала" статьи вне найденного контекста — см. риск ниже)
6. Go сохраняет `Message`, обновляет статус треда

**Риск, который стоит держать в голове**: раз финальная генерация в Go, а не в специализированном ML-сервисе — валидация, что модель не цитирует несуществующие статьи (галлюцинация закона), должна быть реализована именно в Go после получения ответа (сверка `sources` из ответа LLM со списком, который вернул RAG). Стоит явно заложить эту проверку в код, а не полагаться только на промпт.

## 5. Каталог ошибок — обновлённый §5.2

### 5.2 Обработка запроса агентом (пересобрано под новую архитектуру)

| Сценарий                                                                                   | Что делает бэкенд                                                                                                                                                                                                   | Что видит пользователь                                                                                              |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| LLM-провайдер не отвечает (таймаут/5xx) при прямом вызове из Go                            | Go делает до 2 повторов с backoff; если не помогло — `thread.status = error`, кредит услуги возвращается на баланс                                                                                                  | "Не удалось обработать запрос, попробуйте ещё раз. Оплата возвращена на баланс"                                     |
| LLM вернул невалидный/неразбираемый JSON                                                   | то же самое (`status=error`, возврат кредита), сырой ответ модели пишется в лог                                                                                                                                     | тот же текст, что выше                                                                                              |
| LLM процитировал источник, которого не было в результатах RAG (подозрение на галлюцинацию) | ответ не блокируется полностью, но помечается флагом `unverified_sources=true` в логах для последующего разбора; в проде — обсудить с продуктом, стоит ли это дополнительно предупреждать пользователя в интерфейсе | по умолчанию — ответ показывается как есть, разметка "непроверенный источник" опциональна (открытый вопрос, см. §8) |
| Модель отказалась отвечать / контент заблокирован модерацией провайдера                    | `status=error`, возврат кредита, без показа формулировки отказа модели                                                                                                                                              | "Не удалось обработать запрос, попробуйте переформулировать"                                                        |
| Python `/internal/rag/search` недоступен                                                   | Go продолжает без источников (деградация, а не полный отказ): вызывает LLM без RAG-контекста, помечает ответ `sources_degraded=true` в логе                                                                         | ответ приходит, но может быть без ссылок на статьи — не блокирующая ошибка                                          |
| Python `/internal/files/extract` или `/internal/stt` недоступен                            | это Python-сервис — здесь применяется отдельная логика (см. v3 §5.3 и §5.4, без изменений): для файлов — сообщение уходит с пометкой "файл не прочитан", для голоса — ошибка до создания сообщения                  | см. v3 §5.3/§5.4                                                                                                    |
| Агент запросил уточнение (`needs_clarification: true`)                                     | не ошибка: `status = clarify`, кредит не возвращается                                                                                                                                                               | ассистент задаёт уточняющий вопрос                                                                                  |
| Генерация документа: LLM отработал, но `/internal/documents/render` (Python) упал          | ошибка изолирована к операции генерации файла — текст ответа в чате сохраняется, `doc`-кредит возвращается, статус самой операции рендера = `error`                                                                 | "Ответ готов, но не удалось подготовить файл документа. Попробовать ещё раз"                                        |

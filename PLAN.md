# Zan — план реализации фронтенда

Источники, на основе которых собран план:

- `Design/Zan.dc.html` — интерактивный прототип (единственный файл, все экраны в одном месте)
- `Design/uploads/zan-product-brief.md` — продуктовый бриф v2 (требования шире, чем показано в прототипе — см. §2)
- `backend-roadmap.md` — контракт с бэкендом v4 (Go + Python), роуты и статус-модель

Прототип — не финальный дизайн, а рабочий макет поведения (тема, экраны, состояния). Он написан не на React, а на собственном DSL (`x-dc`, `sc-if`, `sc-for`) для превью. **Переносим не разметку, а поведение, тексты (RU/KZ) и design-токены (CSS-переменные).**

Репозиторий — монорепо: код фронтенда лежит в `frontend/` (реализован, см. `instructions.md`), этот план и остальные документы — в корне. Все пути ниже (`shared/...`, `app/...`, `features/...`) — относительно `frontend/src/`, если не указано иное.

## 4. Stage 0 — Foundation (обязательный, блокирует все остальные стадии)

Всё, от чего зависят страницы, но что само не является страницей.

Архитектурные правила (слои, состояние, логирование, naming, ревью-чеклист) — зафиксированы отдельно в `FRONT_CODING_STANDARDS.md`, обязательны с первого коммита Stage 0, не переизобретаются по ходу. Все значения цвета/типографики/spacing/радиусов/z-index/breakpoints — из `FRONT_DESIGN_SYSTEM.md`, `tokens.css` и `tailwind.config` реализуют его один в один, без собственных значений мимо документа.

**Состав:**

1. Инициализация проекта (Vite + React + TS + Tailwind + ESLint + Prettier + Vitest).
2. `shared/styles/tokens.css` — светлая/тёмная тема, 1:1 перенос переменных из Zan.dc.html:18-29 (`--bg`, `--surface`, `--ink`, `--accent`, `--danger` и т.д.), плюс `prefers-color-scheme` как fallback для системной темы.
3. Layout-shell: `Header` (лого, нав по 4 разделам, RU/KZ, тема) + `Main` + область композера. Адаптивность: на ширинах < 640px навигация уходит в нижний таб-бар или сворачивается в меню — в прототипе это не решено (nav — просто ряд кнопок, который на телефоне переполнится), это отдельное дизайн-решение Stage 0, не косметика.
4. Роутинг: `/`, `/history`, `/tariffs`, `/settings`, ленивая загрузка каждой страницы.
5. Сторы (Zustand): `useThemeStore`, `useLangStore`, `useSessionStore` (`session_id`, баланс), `useModalStore` (для общих модалок — не мешать модалку оплаты в стейт страницы Chat, как это сделано в прототипе Zan.dc.html:881-883).
6. UI-кит (`shared/ui`): `Button`, `IconButton`, `Input`, `Textarea`, `Select`, `Card`, `Badge`, `Tabs`, `EmptyState`, `Skeleton`, `Toast`, `QuantityStepper`, а также **общие модалки** `ConfirmModal` (M1) и `PaymentModal` (M3) — они переиспользуются минимум двумя страницами каждая (см. таблицу §1), поэтому живут здесь, а не в конкретной фиче.
7. API-клиент (`shared/lib/api.ts`): базовый `fetch`-враппер, `X-Trace-Id`, единая обработка ошибок по каталогу backend-roadmap.md §5.2, автологирование каждого запроса (старт/успех/ошибка) через `logger`.
   7b. `shared/lib/logger.ts` — реализация контракта из `FRONT_CODING_STANDARDS.md` §4 (уровни debug/info/warn/error, отправка warn/error на `/logs/client` в проде, `traceId` сквозной с API-клиентом).
8. Индикатор баланса пользователя в шапке (gap из §2) — данные пока мок, реальный источник подключится в Stage 6.
9. `useRole()` — заглушка (сейчас всегда `"admin"`), только чтобы `/settings` не завязывался жёстко на "видно всем" (brief 3.6, §6) — реальная проверка появится позже без переписывания страницы.
10. ErrorBoundary + страница 404.

**Готово, когда:** `npm run dev` (из `frontend/`) показывает работающий shell (шапка, переключатели темы/языка кликабельны, 4 пустых роута открываются), `npm run build` и `npm run lint` проходят чисто. ✅ Выполнено — см. `instructions.md`.

## 5. Стадии по страницам (после Stage 0 — реализуются независимо друг от друга и в любом порядке/параллельно)

Каждая стадия ниже: (а) работает на моках, без реального бэкенда — подключение API вынесено в Stage 6; (б) использует только компоненты из Stage 0's `shared/ui`; (в) не зависит от кода других стадий этого раздела.

### Stage 1 — Chat (главный экран)

Источник: Zan.dc.html:64-159, 397-427, 536-554; brief 3.1-3.2.

- Пустое состояние: заголовок/подзаголовок + **быстрые темы** (gap, новый элемент — 4 чипа, клик подставляет черновик в композер).
- Композер: текст, вложение файла (иконка меняется по типу: PDF/DOCX/изображение — gap), голосовой ввод (запись → STT текст в поле, редактируемо перед отправкой). Без явного toggle "Подготовить документ" — вопреки brief 3.1, сознательное решение продукта (2026-09-20): "нужен документ" определяет бэк по контексту сообщения (Stage 6), не пользователь явным контролом; пока бэка нет — мок-эвристика по тексту (`documentIntent.ts`).
- Тред: пузыри пользователь/ассистент, сворачиваемый блок источников, 👍/👎, карточка вложенного файла, карточка готового документа (скачать PDF/Word/исправить).
- `OnboardingModal` (M5) — показывается один раз при первом входе (флаг в `localStorage`, не в проп, как в прототипе Zan.dc.html:817).
- Использует `PaymentModal` из Stage 0 при отправке первого сообщения в новом треде (brief 3.4 — оплата за тред, не за сообщение).
- Моки: `features/chat/mocks.ts`, структура на основе `SOURCES`/`FINDINGS` из Zan.dc.html:707-731.

### Stage 2 — История обращений

Источник: Zan.dc.html:162-210.

- Поиск (debounce) + фильтр по статусу (6 статусов: очередь/обработка/уточнение/готово/ошибка/отменён).
- Карточка треда: статус-бейдж, превью последнего сообщения, дата, счётчик сообщений, удаление через `ConfirmModal` (Stage 0).
- Пустое состояние (нет тредов / нет результатов фильтра — два разных empty-state, в прототипе они смешаны в один `historyEmpty`, Zan.dc.html:176, разделяем).
- Клик по треду → переход в Chat с этим тредом (роутинг `/?thread=:id`, реализация — заглушка до Stage 6).
- Зависит только от Stage 0 (`ConfirmModal`, `Badge`).

### Stage 3 — Тарифы (пользователь)

Источник: Zan.dc.html:213-247; brief 3.5.

- Сетка пакетов (карточка: название, состав, цена/старая цена при скидке, кнопка "Купить" → `PaymentModal`).
- Блок "свой набор" → `CustomOrderModal` (M4): степпер количества по каждой услуге (переиспользует `QuantityStepper` из Stage 0, но сама модалка — своя, не путать с админской M2: разная семантика — здесь нет поля скидки и нет привязки "тариф = набор услуг с историей редактирования").
- Backlog-заметка (не блокирует Stage 3): место под будущий тариф "Безлимит на месяц" — верстать сетку так, чтобы добавление 5-й карточки не ломало layout.

### Stage 4 — Настройки (3 независимые вкладки, можно делать параллельно/разными людьми)

Общее: обёртка `SettingsPage` с `Tabs` (Промпты/Тарифы/Аналитика) и `useRole()`-гейтом из Stage 0.

- **4a. Промпты** (Zan.dc.html:266-283) — 2 textarea (агент "Вопрос-ответ", агент "Документы"), кнопка "Сохранить", guard на несохранённые изменения при уходе со страницы. Источник текста — `AgentPrompt` через API (backend-roadmap.md:22), не хардкод.
- **4b. Тарифы (админ)** (Zan.dc.html:285-354) — список услуг (инлайн-редактирование цены/названия), сетка тарифов с edit/delete → `BundleEditModal` (M2: имя, скидка %, степпер по каждой услуге, live-пересчёт суммы — логика 1:1 из Zan.dc.html:1024-1042, но без глобального `state`-объекта — считается через `react-hook-form` + `useMemo`).
- **4c. Аналитика** (Zan.dc.html:356-390) — 3 метрики-плитки + список статусов с барами (доля от максимума). Полноценный чарт не нужен — 6 категорий, горизонтальные бары читаются лучше пирога; если позже добавится динамика по времени — тогда уже нужен линейный график (см. навык `dataviz`, не требуется на этом этапе).

## 6. Sequencing / зависимости

```
Stage 0 (Foundation)
   │
   ├──▶ Stage 1 (Chat)         ─┐
   ├──▶ Stage 2 (History)       │  независимы друг от друга,
   ├──▶ Stage 3 (Tariffs)       │  можно в любом порядке / параллельно
   └──▶ Stage 4 (Settings)     ─┘
             │
             ▼
       Stage 5 (Responsive + a11y аудит по всем страницам сразу)
             │
             ▼
       Stage 6 (Backend-интеграция — тоже режется по страницам,
                 см. таблицу ниже, каждую часть можно катить отдельно)
```

Единственные точки пересечения между стадиями 1-4 — общие компоненты из Stage 0 (`ConfirmModal`, `PaymentModal`, `QuantityStepper`, `Badge`). Если после Stage 0 обнаружится, что нужен ещё один общий компонент — добавлять его в `shared/ui`, а не дублировать в двух фичах.

## 7. Stage 5 — Адаптивность и accessibility (пост-обход по всем страницам)

Выполняется после того, как у страниц 1-4 есть рабочая вёрстка (не обязательно после ВСЕХ сразу — можно проходить по каждой странице сразу за её стадией).

Чек-лист (по каждому экрану):

- [ ] Брейкпоинты: 320 / 375 / 768 / 1024 / 1440 — без горизонтального скролла нигде
- [ ] Touch-таргеты ≥ 44×44px, интервал ≥ 8px (кнопки-иконки в прототипе местами меньше — поправить)
- [ ] Контраст текста ≥ 4.5:1 в обеих темах (проверить `--muted` на `--surface` в dark, Zan.dc.html:24-29)
- [ ] Все icon-only кнопки — с `aria-label` (в прототипе их нет ни у одной, Zan.dc.html:409, 416, 422)
- [ ] Фокус видим (`:focus-visible`), не убирается global reset
- [ ] Модалки: focus-trap, закрытие по `Esc`, `aria-modal="true"`, возврат фокуса на триггер
- [ ] `prefers-reduced-motion` уважается (анимация записи голоса `zanPulse`, Zan.dc.html:34)
- [ ] Safe-area отступы снизу для композера на iOS (`env(safe-area-inset-bottom)`)

## 10. Структура папок (реализовано в Stage 0 — см. `frontend/`)

```
frontend/
  src/
    app/
      layout/                # AppShell, Header, MobileNav, BalanceIndicator

                              # EmptyState, Skeleton, QuantityStepper, Modal, ConfirmModal,

      lib/                   # api.ts, env.ts, logger.ts, traceId.ts, cn.ts, format.ts
      hooks/                 # useRole, useFocusTrap
      stores/                # useThemeStore, useLangStore, useSessionStore,

      chat/        ChatPage.tsx (пока плейсхолдер — наполняется в Stage 1)
```
